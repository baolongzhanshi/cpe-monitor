## 我们采用的方向

采用原生 Windows 控制台与独立后台分离的形式。用户最终选择软件自带界面，Windows 客户端使用 .NET 10 Windows Forms 原生控件，不创建 WebView。窗口隐藏或最小化后暂停展示请求，短信同步和 PushPlus 仍由后台执行。安装包内置运行环境，用户无需安装开发工具。

架构分成三部分：原生控制台、本机后台、华为设备适配层。设备认证、解密和 PushPlus Token 留在本机后台；控制台读取共享实时缓存和本地短信快照。窗口隐藏时停止仅用于展示的刷新任务，保留必要的后台同步。Web 控制台作为可选入口保留，其请求同样复用共享缓存。

不把官网 Vue 技术栈当作低资源的证明，也不直接照搬缺失的设备通信算法。优先复用本项目已验证的 H153-381 认证及短信解密逻辑。

## 实施顺序

1. 完成原生 Windows 客户端：统一产品名 CPE Monitor 与版本 0.2.0，核验首次配置、重复启动复用后台、托盘生命周期、退出清理和配置兼容。
2. 减少短信重复扫描：首次建立完整快照；后续检查计数和最新联系人记录，有变化完整同步，无变化每分钟完整核对。数量相同仍可能有新短信，不能仅凭计数相同跳过。部分失败不推进完整快照状态。
3. 实时数据接口复用进行中的请求和短期缓存，避免多个视图同时重复访问 CPE。前台恢复后立即读取，窗口隐藏或最小化时暂停展示刷新。
4. 若实测后台仍是主要占用，再将常驻 Next.js 服务拆成精简本地接口服务。此步骤涉及路由与打包迁移，需单独回归，不能当作当前已完成的改动。
5. 为推送补上持久化待发送状态、失败重试和逐渠道记录，避免失败后不补发或入库失败重复发送。首次同步默认不推历史短信。

以上为实施规划，不代表已经生成新安装包。当前运行程序保持原状，未停止、重启或访问设备进行测试。

## 验收标准

- 安装即可运行，原有设备配置和数据保持可用，无额外管理员密码。
- 关闭控制台后后台仍检查短信；重复运行不会新建第二套后台。
- 固定相同短信检查周期、相同设备和相同采样窗口比较资源；前台开启时计入原生窗口与本地后台成本，如另开 Web 控制台则单独计入浏览器成本。
- 检查无新短信、连续新短信、计数不变但内容变化、设备断线重连、分页失败及推送失败的流程。以模拟设备和模拟推送服务先做回归，不向用户设备写入或真实发送测试通知。
- 分别记录设备发现新短信、写入本地、推送平台受理和页面显示的时间；平台受理不能表述为消息已经送达。
- 报告工作集、私有提交、CPU、进程、句柄与线程；工作集合计可能重复计算共享页，私有提交不是物理 RAM，不用短期离散样本断言不存在内存泄漏。
- 每次应用改版前完成源码、Git、对应安装包、在线数据库与配套运行密钥的完整备份；发布下载新版后再次备份。敏感数据仅本机加密保存。
